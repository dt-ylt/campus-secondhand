## 二、面试高频题 + 参考答案

### 1. 项目介绍类

**Q：简单介绍一下你的项目？**
A：校园二手交易平台，前后端分离。后端用 Spring Boot 2.7 + MyBatis-Plus + MySQL，实现用户注册登录、商品发布/编辑/删除、分页列表筛选、收藏、留言、管理员审核；图片上传用 MinIO 对象存储；首页商品列表用 Redis 做缓存加速；接口用 JWT 鉴权。前端用 Vue3 + Vite + axios。开发过程分 9 个阶段，每个阶段 git 提交一次，有完整的开发记录。

**Q：为什么选择这些技术？**
A：Spring Boot 生态成熟、开发效率高；MyBatis-Plus 免写 SQL 提升效率；MySQL 免费稳定；Redis 内存数据库适合做缓存；MinIO 是开源对象存储，自己部署省云存储费用；Vue3 是当前主流前端框架，组合式 API 更灵活。

### 2. Spring Boot / Java 基础

**Q：Spring Boot 的自动配置原理？**
A：`@SpringBootApplication` 里包含 `@EnableAutoConfiguration`。启动时 Spring 会读取依赖 jar 里 `META-INF/spring.factories` 中声明的自动配置类，根据当前 classpath 的依赖和配置文件，用 `@ConditionalOnXxx` 条件注解按需创建 Bean。比如 classpath 里有 HikariCP 和 MySQL 驱动、配置文件里配了数据源 url，就会自动创建 DataSource。

**Q：什么是 Starter？**
A：Starter 是依赖的聚合包，比如 `spring-boot-starter-web` 把 Spring MVC、Tomcat、Jackson 等打包在一起，引入一个依赖就能用整套 Web 能力。

**Q：什么是 IoC / DI？**
A：控制反转 IoC——对象的创建和管理交给 Spring 容器，而不是自己 new。依赖注入 DI 是 IoC 的实现方式，通过 `@Autowired` 把需要的依赖自动注入进来，降低耦合。

**Q：`@Autowired` 和 `@Resource` 的区别？**
A：`@Autowired` 是 Spring 的，默认按类型注入；`@Resource` 是 JDK 标准，默认按名称注入。实际使用中两者都能满足需求。

### 3. MyBatis-Plus / 数据库

**Q：分页查询怎么实现？为什么要配分页插件？**
A：MP 的 `selectPage` + 分页插件 `MybatisPlusInterceptor`。插件会在 SQL 里拼上 `LIMIT`。**不配插件的话分页是假的**——SQL 没有 LIMIT，会把全表查出来，这是 MP 最常见的坑。

**Q：什么是逻辑删除？**
A：删除时不真正 DELETE，而是把 `deleted` 字段改成 1，查询自动加 `WHERE deleted=0` 过滤。好处：数据可恢复、不会让收藏/留言指向不存在的商品。用 `@TableLogic` 注解标识。

**Q：什么是 N+1 查询？你怎么解决的？**
A：查询列表后，如果循环里对每行再做关联查询，就是 1+N 次查询，性能差。我的做法：列表查出来后，先收集所有商品 id，用一次 `IN` 批量查询图片/分类/卖家，再在内存里按 id 分组组装，总共 3 次查询而不是 1+N 次。

**Q：索引是什么？最左前缀原则是什么？**
A：索引类似书的目录，加速查询。复合索引 `(category_id, status)` 可以命中 `category_id` 单独查和两者一起查，但**不能**单独命中 `status` 查——必须从最左列开始用，这就是最左前缀原则。

**Q：为什么金额用 BigDecimal 不用 double？**
A：浮点数有精度问题（`0.1+0.2≠0.3`），存钱会算错。BigDecimal 是精确十进制，配合数据库 DECIMAL 类型。

**Q：事务是什么？为什么发布商品要加 `@Transactional`？**
A：事务保证一组操作要么全部成功要么全部回滚。发布商品要同时插商品表和图片表，如果图片插入失败但商品插成功了，就会出现"有商品没图"的脏数据，所以加事务保证原子性。

### 4. Redis 缓存

**Q：为什么用 Redis？缓存流程是什么？**
A：首页商品列表高频读，每次都查数据库慢。Redis 是内存数据库，读快几十倍。流程：先查缓存，命中直接返回；未命中才查数据库，并把结果序列化写入缓存（设 5 分钟过期）；商品数据变更时清空列表缓存，下次查询重建。

**Q：怎么保证缓存和数据库一致？**
A：本项目采用"先更新数据库，再清缓存"的策略——写操作改完数据库就删掉对应缓存，下次读取重新查库并回写缓存。简单可靠，最终一致。

**Q：缓存穿透、击穿、雪崩是什么？怎么解决？**（高频中的高频）
- **穿透**：查一个不存在的 key，缓存和数据库都没有，每次请求都打到数据库。解决：缓存空值、布隆过滤器。
- **击穿**：某个热点 key 过期瞬间，大量请求同时打到数据库。解决：互斥锁，让一个请求去重建缓存，其他等待。
- **雪崩**：大量 key 同时过期，数据库瞬间压力爆炸。解决：过期时间加随机值错峰。

### 5. JWT / 鉴权

**Q：JWT 的原理？**
A：JWT 由三段组成：Header（算法）、Payload（身份信息：userId、过期时间等）、Signature（用密钥对前两段签名）。服务端用密钥签名生成 token，客户端存起来，每次请求放进 `Authorization` 头。服务端用同一个密钥验签，验过就知道是谁。因为带签名，内容无法被篡改。

**Q：JWT 的优缺点？**
A：优点：无状态，服务器不用存 session，方便水平扩展、多端登录。缺点：无法主动让 token 失效，只能等过期；token 一旦泄露就被人冒用。所以一般设置较短的有效期。

**Q：登录鉴权的完整流程？**
A：登录时校验用户名密码 → 生成 JWT token 返回 → 前端存 localStorage → 每次请求 axios 拦截器自动加 `Authorization: Bearer token` → 后端 JwtInterceptor 验签、取 userId 放进 request 属性 → Controller 用 `@RequestAttribute` 拿 userId。

**Q：拦截器怎么实现？管理员权限怎么控制？**
A：实现 `HandlerInterceptor` 的 `preHandle` 方法，在 `WebMvcConfigurer` 里注册。本项目两层：第一层 JwtInterceptor 拦所有请求验 token（放行注册/登录/浏览）；第二层 AdminInterceptor 只拦 `/admin/**`，从数据库查当前用户的 role，不是 1 就抛 403。

**Q：401 和 403 的区别？**
A：401 未登录/凭证无效；403 已登录但没权限。

### 6. Vue3 前端

**Q：`v-model` 原理？**
A：语法糖，等价于绑定 `value` + 监听 `input` 事件，实现表单双向绑定。

**Q：组件数据请求放在哪个生命周期？**
A：`onMounted`，页面挂载后发请求（如进入首页加载商品列表）。

**Q：axios 拦截器是干嘛的？**
A：请求拦截器在每次请求前自动加 token；响应拦截器统一处理后端返回的 `{code,message,data}`，code 不是 200 就 alert 提示并 reject，401 则清 token 跳登录页。

**Q：开发时怎么解决跨域？**
A：开发用 Vite 代理：前端请求 `/api` 开头的地址，Vite 转发到后端 8080 并去掉 `/api` 前缀，浏览器视角是同源，无跨域问题。生产部署用 Nginx 反向代理，同理。

### 7. 部署

**Q：项目怎么部署？**
A：后端 `mvn package` 打成可执行 fat jar，服务器装 JDK17，上传 jar 用 `nohup java -jar xxx.jar &` 后台运行；前端 `npm run build` 生成静态文件，用 Nginx 托管，并把 `/api` 反向代理到后端端口。数据库 MySQL、Redis、MinIO 都部署在服务器上。

### 8. 项目可改进点（面试官："如果让你继续优化这个项目"）

- 缓存清理用 `keys` 命令在生产换成 `SCAN`，避免阻塞 Redis
- 图片上传加类型/大小校验、压缩、防盗链
- 商品列表分页数据量大时改用游标分页
- 加商品详情页、下单/交易流程、消息通知
- 补充单元测试和集成测试
- 数据库读写分离、连接池参数调优
- 密码加密考虑更高级方案，token 增加刷新机制
