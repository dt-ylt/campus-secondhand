## 阶段 0：建 GitHub 仓库 + git 基础

### git 是什么？
git 是个"代码存档器"。你写代码写到某个程度，可以"存一个档"，以后随时能回到这个状态。就像游戏存档点。

### 为什么要传到 GitHub？
GitHub 是个"代码云盘"。把代码传上去有三个好处：
1. **备份**：电脑坏了代码还在
2. **展示**：面试官能看你写过的代码和一步步的开发过程（这个很重要）
3. **协作**：多人一起写同一个项目

### add / commit / push 是啥意思？
- `git add`：把改动"选中"，准备存档（像把文件放进待打包的箱子）
- `git commit`：正式存档，生成一个版本快照（打包封箱，贴个标签 = commit 注释）
- `git push`：把存档传到 GitHub 云端（把箱子寄出去）

三步是固定节奏：改完代码 → add → commit → push。每完成一个阶段就跑一遍。

### 项目目录结构
我们用"单仓库 monorepo"，一个仓库里同时放前后端：
```
campus-secondhand/
├── backend/    后端代码（Spring Boot）
├── frontend/   前端代码（Vue3，阶段8写）
├── sql/        数据库脚本
└── docs/       文档（本文件就在这）
```

## 阶段 1：数据库设计

### 数据库是啥？
存数据的地方。可以想象成一个仓库，里面摆着一排排"表格"。

### 表是啥？
像 Excel 表格：有列（字段）和行（一条条数据）。比如 `sys_user` 表存所有用户，每行一个用户。

### 6 张表各存什么
| 表名 | 存什么 |
|---|---|
| sys_user | 用户（普通用户 + 管理员） |
| category | 商品分类 |
| product | 商品（核心表） |
| product_image | 商品图片 |
| favorite | 收藏 |
| product_comment | 留言 |

### 几个关键设计（面试常问）
1. **金额用 DECIMAL 不用 FLOAT**：浮点数算钱会丢精度（`0.1+0.2` 在计算机里不等于 `0.3`），DECIMAL 精确存钱。
2. **密码加密（BCrypt）**：密码绝不存明文。BCrypt 是单向加密（不可逆），而且同一密码每次加密结果都不同（带随机"盐"），很难被破解。
3. **逻辑删除（软删除）**：删商品不是真从数据库删，是标记 `deleted=1`，查询时自动过滤掉。好处：能恢复、不会让收藏/留言指向"不存在的商品"。
4. **索引**：像书的目录，加速查找。给经常用来查询的字段建索引。复合索引有"最左前缀原则"（用复合索引必须从最左边的字段开始用）。
5. **utf8mb4 字符集**：MySQL 的 `utf8` 是阉割版（存不了 emoji 😄），`utf8mb4` 才是完整的 UTF-8。

## 阶段 2：后端初始化 + 公共组件

### Spring Boot 是啥？
一个帮你快速搭 Java 网站服务的框架。没它你得手动配置一堆东西；用了它，一个带 main 方法的类就能跑起一个网站服务。

### Maven 是啥？
管"依赖"（第三方代码包）的工具，类似前端的 npm。你想要某个功能（比如连数据库），就在 `pom.xml` 里声明依赖，Maven 自动帮你下载。配了阿里云镜像后下载很快。

### pom.xml
Maven 的清单：声明项目用了哪些依赖、Java 版本、打包方式等。

### application.yml（配置文件）
放端口、数据库地址、各种参数。我们拆成两个：
- `application.yml`：主配置，**会传 GitHub**
- `application-local.yml`：数据库密码等敏感信息，**被 .gitignore 忽略，不传**（密码不能上 GitHub）

### 三个公共组件
1. **统一返回 Result**：所有接口返回统一格式 `{code, message, data}`。前端处理逻辑统一：看 code 是不是 200。
2. **全局异常处理器**：不管哪里出错，统一接住，转成 Result 返回。Controller 里不用写 try-catch，代码干净。
3. **JWT 工具类**：生成/解析 token，登录鉴权用。

## 阶段 3：用户模块

### 三层架构（核心思想，面试必问）
一个请求从上到下流过三层：
```
前端请求 → Controller（接请求、校验参数、返回结果）
              ↓
           Service（业务逻辑：查重、加密、校验...）
              ↓
           Mapper（操作数据库）
              ↓
           MySQL
```
分层让代码各司其职：Controller 不关心数据库细节，Service 不关心 HTTP，Mapper 只管跟数据库打交道。清晰、好维护、好测试。

### 注册流程
前端发账号密码 → Controller 接收 → Service 查重（用户名是否已存在）→ 密码 BCrypt 加密 → Mapper 插入数据库。

### 登录流程
前端发账号密码 → Service 按用户名查用户 → 比对密码（`matches`）→ 生成 JWT token → 返回 token + 用户信息。前端把 token 存起来，后续请求带上。

### JWT 鉴权（通行证）
- 登录成功 → 服务器发一张 token（通行证）
- 之后每个需要登录的请求 → 前端带上 token
- 后端拦截器验 token：有效就放行并记住"你是谁"，无效就返回"未登录"

token 里装着你的身份信息，还有签名防伪造。

### 参数校验（@Valid）
DTO 上加 `@NotBlank`、`@Size` 等注解，Controller 参数加 `@Valid` 触发校验。参数不合法直接返回提示（如"用户名不能为空"），不用写一堆 if。

### BCrypt 加密
注册时 `encode` 加密存库，登录时 `matches` 比对。盐是随机的，防"彩虹表"破解。

### 安全小技巧
登录失败时，"用户不存在"和"密码错误"都返回同一句"用户名或密码错误"，不告诉攻击者用户名是否注册过（防"用户枚举攻击"）。
